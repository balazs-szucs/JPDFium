# DeviceCMYK colour pipeline — status and plan

## What is implemented

- DeviceCMYK page-object setters/getters in the JPDFium PDFium patch.
- Source colour-space probe (`FPDFPageObj_GetFillColorSpace` /
  `FPDFPageObj_GetStrokeColorSpace`) so the Java layer can distinguish
  DeviceGray/DeviceRGB/DeviceCMYK from ICC, Separation, DeviceN, Indexed and
  pattern colours.
- `FPDFFormObj_MarkDirty` so child edits inside form XObjects are actually
  regenerated by `FPDFPage_GenerateContent`.
- `PdfColorConverter` preserves existing DeviceCMYK ink values and leaves
  special colours untouched for a CMYK target.
- Image XObjects can be re-encoded as 4-component DeviceCMYK JPEGs, including
  images inside form XObjects when form write-back is available.
- ICC output intents can be written with QPDF.
- `PdfXConverter` bootstraps PDF/X-3/-4 output: CMYK conversion, GTS_PDFX
  output intent, and XMP version/conformance metadata.
- `PdfRecolor` only rewrites DeviceGray/DeviceRGB when the colour-space probe is
  available.

## Required release step

The CMYK path is compiled only when the PDFium header carries the full JPDFium
colour patch. The prebuilt PDFium pin must be built by the `Prebuild PDFium`
workflow from this branch (or a later `embedpdf/main` revision that contains the
patch), then `native/pdfium.version` must be bumped to that release. Until then
`PdfColorConverter.supportsColorSpace(ColorSpace.CMYK)` returns `false` and
`toCmyk()` throws instead of producing a lossy conversion.

The prebuild workflow already runs `native/setup-pdfium.sh`, so it applies the
JPDFium patch automatically. Its release tag is currently derived only from the
EmbedPDF SHA; if that SHA was already released unpatched, a forced rebuild would
overwrite the same tag. Prefer a patch-aware tag (EmbedPDF SHA + JPDFium patch
hash) before republishing, or upstream the patch into `embedpdf/pdfium`.

Do not enable the CMYK feature in a released artifact against a stock PDFium
build. The CI native probe should assert the full capability word
(`JPDFIUM_COLOR_CAP_CMYK_VECTOR`) once the pin contains the patch.

## Implemented in this PR

1. **Profile-aware special colours.** ICCBased fills/strokes can be converted
   through their embedded source ICC profile with `convertSpecialColors(true)`.
   Cal/Lab/Indexed colours use PDFium's colour-space conversion. Separation and
   DeviceN spots stay preserved by default; `convertSpotColors(true)` opts into
   tint-transform conversion and intentionally drops the spot name/overprint
   intent. Patterns are never flattened.
2. **Images inside form XObjects.** The native image pass walks form children,
   and `EPDFImageObj_SetJpeg` preserves `/OC`, `/Intent`, `/Interpolate`,
   `/Name`, `/Metadata`, `/Alternate` and `/Matte`. Alpha-bearing images remain
   skipped.
3. **PDF/X metadata.** Output-intent replacement normalizes both XMP
   `GTS_PDFXVersion` tags. A PDF/X bootstrap API (`PdfXConverter` /
   `PdfOutputIntent.applyPdfx`) now creates a GTS_PDFX output intent and writes
   `GTS_PDFXVersion` / `GTS_PDFXConformance` for PDF/X-3 and PDF/X-4. QPDF has no
   incremental-update writer, so the native path still does a full rewrite; an
   incremental implementation remains future work.
4. **Ghent gate in CI.** `.github/workflows/ghent.yml` builds the patched
   PDFium, downloads the Ghent test pages and runs `GhentOutputSuiteTest`.
5. **Form deduplication.** `FPDFFormObj_GetObjectNumber` provides a stable form
   identity and the document-level conversion state visits a shared form once.
6. **Performance.** In-memory and file conversions share one ICC transform per
   document; the patched native uses a dictionary probe instead of rendering
   images just to test alpha; form traversal reuses the page object slots.

## Remaining future work

- Add a QPDF incremental-update writer (or a PDFium catalog edit API) so output
  intents do not require a full-file rewrite.
- Preserve overprint/spot semantics when converting spots, instead of dropping
  them in `convertSpotColors(true)`.
- Add alpha-preserving CMYK JPEG encoding for masked images.
- Add rendered Ghent comparisons for the PDF/X output-intent path and for
  recolour scenarios.
- Benchmark large form-heavy documents and consider a document-level form
  cache rather than only a visited set.

## Ghent test

Download the Ghent PDF Output Suite 5.0 test pages, then run:

```bash
GHENT_DIR=/path/to/Ghent_PDF_Output_Suite_V50_Testpages \
  ./gradlew :jpdfium:integrationTest --tests '*GhentOutputSuiteTest'
```

The gate requires a patched PDFium with vector CMYK, the colour-space probe and
`FPDFFormObj_MarkDirty`. It converts every PDF shipped with the suite (test
pages, reference atlas, explanatory PDFs) and asserts that every rendered page
is visually unchanged after `PdfColorConverter.toCmyk()`. Conformance test
pages use a strict MAE bound; RGB explanatory PDFs use a looser visual-sanity
bound. `PdfXCmykCorpusTest` runs the same round trip over a configurable slice
of the real PDF corpus.
